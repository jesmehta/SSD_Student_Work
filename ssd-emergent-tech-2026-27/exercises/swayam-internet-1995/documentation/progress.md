Important Historical Design Rule

The Web Design Museum gallery should be used as a visual and discovery
reference, while the simulator's own historical logic remains authoritative.

A website appearing in the gallery does not automatically mean that it
should be available on every date in 1995.

The future Time Engine should eventually determine:

whether the site existed on the selected date

what version/state of the site was available

what URL the user would have entered

whether the site was reachable

whether the selected browser could display it

whether the page should load successfully, slowly, partially, or fail

This preserves the project's core principle of date-dependent historical
Internet behaviour.

# Historical Accuracy Direction

The simulator will distinguish between:

## January--August 23, 1995

Windows Chicago / pre-release Windows 95 environment.

## August 24--December 1995

Retail Windows 95 environment.

The Windows 95 retail release date is August 24, 1995.

This distinction will eventually be controlled by the Time Engine.

Historical accuracy will also apply to the simulated Internet.

Browser capabilities, websites, connection speeds, available

technologies, and interface behaviour should correspond to the selected

historical date.

# Development Principles

1. Historical realism takes priority over modern convenience.

2. The simulator must remain playable in a modern browser while

visually and behaviorally representing 1995.

3. The date slider will eventually control the capabilities of the

simulated Internet.

4. Website states must be date-dependent.

5. Browser capabilities must evolve according to the selected date.

6. Dial-up behaviour should feel intentionally slow.

7. Modern UI conventions should not visually leak into the simulated

1995 environment.

8. New features should be implemented as modular Vanilla JavaScript.

9. Reference images supplied during development should be used when

reproducing historical UI artwork.

10. Visual assets should be preserved as closely as possible rather

than replaced with generic modern equivalents.

11. CSS cleanup must not remove intentional visual overrides required

for historical accuracy.

12. New functionality should be added without compromising the

established Windows 95 / 1995 visual language.
