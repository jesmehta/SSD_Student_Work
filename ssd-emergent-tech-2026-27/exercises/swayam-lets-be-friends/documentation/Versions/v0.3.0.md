# v0.3.0 — Friendly Camera Interaction

**Date:** 21 August 2026

**Status:** Working Prototype

---

# Overview

v0.3.0 introduces the first friendly interaction after the player accepts the incoming video call.

The purpose of this version is to establish a feeling of connection and comfort between the player and the digital character.

The character now reacts to the player being visible on camera and asks the player to perform simple actions.

At this stage, the interactions are intentionally simulated.

Actual facial recognition and movement detection will be introduced in v0.4.0.

---

# Goal

The emotional purpose of this version is:

**Connection**

↓

**Comfort**

↓

**Familiarity**

The player should begin to feel that the digital character is genuinely interested in them.

The character should feel friendly and curious.

Nothing should feel threatening yet.

---

# Added

## Friendly Camera Introduction

After the player accepts the incoming call, the camera opens and the character says:

> Oh...

> There you are.

> Hi, [name]!

> It's nice to finally see you.

This establishes the transition from the text-based conversation into the camera interaction.

---

# Wave Interaction

The character asks:

> Can you wave?

The player is presented with:

**👋 I waved**

After selecting the button, the character responds:

> Haha!

> You actually did it!

This creates the first direct interaction between the player and the camera-based character.

---

# Smile Interaction

The character then asks:

> Can you smile for me?

The player is presented with:

**😊 I smiled**

After selecting the button, the character responds:

> That's a nice smile.

> I like seeing you like this.

This is intended to make the interaction feel personal and friendly.

---

# User Interface

A new camera interaction container was introduced.

It contains buttons that appear only when the character asks the player to perform an action.

The buttons use a minimal style consistent with the camera interface.

The buttons are:

- subtle
- rounded
- translucent
- white
- positioned beneath the dialogue

The interface does not introduce unnecessary visual elements.

---

# Technical Implementation

## Dialogue

Camera interaction dialogue is stored separately in:

`dialogue.js`

The following dialogue group was added:

`DIALOGUE.cameraInteraction`

It contains:

- `wavePrompt`
- `waveResponse`
- `smilePrompt`
- `smileResponse`

This keeps the character's dialogue separate from the main interaction logic.

---

# Simulated Interaction

The wave and smile interactions are currently simulated.

The application does **not** actually determine whether the player:

- waved
- smiled
- performed the requested action

Instead, the player confirms the action using the corresponding button.

This is temporary.

The purpose is to establish the interaction structure before introducing face tracking.

---

# Why Face Tracking Is Not Included Yet

Real face tracking is being deliberately separated into the next milestone.

This keeps v0.3.0 simple and makes it possible to test the emotional experience independently from the technical complexity of facial recognition.

The next version will replace the simulated interaction system with actual camera-based tracking.

---

# Current Camera Behaviour

The camera currently:

- requests permission after the conversation.
- opens after accepting the call.
- displays the webcam full-screen.
- mirrors the webcam horizontally.
- displays white dialogue over the camera.
- remains visually friendly.
- does not manipulate the user's face.

---

# Horror Status

No horror effects have been introduced.

There are currently no:

- movement delays
- glitches
- flickers
- black eyes
- unnatural smiles
- facial distortion
- independent replica movements
- disturbing sounds
- possessive behaviour

This is intentional.

The player must first become comfortable with the character.

---

# Known Limitations

## Wave Detection

Not implemented.

The player manually confirms that they waved.

## Smile Detection

Not implemented.

The player manually confirms that they smiled.

## Face Tracking

Not implemented.

## Replica

There is not yet an independently rendered or manipulated replica.

The camera currently displays the player's webcam feed.

# Next Version

## v0.4.0 — Face Tracking

The next milestone will introduce real-time face tracking.

The goal is for the system to actually understand basic aspects of the user's face and movement.

Potential information to track:

- face position
- face size
- head movement
- eye position
- mouth position
- smile state

The purpose is not yet to create horror.

The purpose is to make the replica genuinely respond to the player.
