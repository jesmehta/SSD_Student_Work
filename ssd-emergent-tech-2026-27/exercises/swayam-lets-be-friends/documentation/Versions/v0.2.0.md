# v0.2.0 — Camera & Incoming FaceTime Call

**Date:** 21 August 2026

**Status:** Working Prototype

---

## Overview

v0.2.0 introduces the first camera interaction in **Evil Replica**.

The camera is deliberately not requested when the experience begins.

Instead, the player first develops a relationship with the digital character.

Only after the conversation reaches the appropriate point does the character ask to see the player.

The player then receives an incoming FaceTime-style call.

This creates a natural transition from:

**Conversation**

↓

**Trust**

↓

**Invitation**

↓

**Incoming Call**

↓

**Camera**

---

# Added

## Camera Permission

The browser's camera API is used to request access to the user's webcam.

The camera request happens only after the player reaches the camera stage.

The browser's:

`navigator.mediaDevices.getUserMedia()`

API is used to access the camera.

---

## Incoming Call

A custom incoming FaceTime-inspired popup was introduced.

The popup contains:

- Incoming FaceTime
- Unknown
- Generic profile avatar
- Accept button
- Decline button

The popup is:

- centered
- relatively small
- horizontally stretched
- pill-shaped
- dark
- minimal

The interface intentionally avoids unnecessary elements.

---

## Camera

After the player accepts the call:

- Browser camera permission is requested.
- The webcam becomes visible.
- The video fills the screen.
- The video is mirrored horizontally.
- The initial camera dialogue appears over the video.

---

# Dialogue

The camera stage currently introduces the player with short dialogue.

Example:

> Oh.

> There you are.

> Hi, [NAME].

The dialogue is displayed using the existing typing system.

When the camera is active, the dialogue changes from black to white so it remains visible over the webcam.

---

# Interaction

The player can:

### Accept

Accepting the call opens the camera.

### Decline

Declining the call returns the player to the dialogue system.

---

# Development Shortcuts

## Space Bar

Pressing the Space bar skips the currently typing dialogue line.

This is useful during testing without affecting the normal experience flow.

---

## Ctrl + S

During development, pressing:

`Ctrl + S`

skips the remaining conversation and moves directly to the incoming call.

This is only a development/testing shortcut.

It prevents the developer from having to replay the entire conversation every time the camera needs to be tested.

---

# Important Bug Fix

## Dialogue Restart After Camera Activation

An earlier implementation had a problem where the previous dialogue sequence could continue running after the camera was activated.

This resulted in the conversation restarting or appearing again underneath the camera.

The dialogue system was changed to use a dialogue session identifier.

When the experience moves to the camera stage:

1. The current dialogue session is invalidated.
2. Existing typing timers are stopped.
3. Delayed dialogue callbacks are cancelled.
4. The camera stage begins independently.

This prevents old dialogue from returning after the camera has opened.

# UI Improvements

The incoming-call interface went through several iterations during this version.

### Earlier version

The initial design was too large and resembled a full-screen mobile call interface.

### Second version

The interface was changed to resemble a desktop notification.

### Final v0.2.0 direction

The final version uses:

- A small centered popup.
- Stretched pill shape.
- Dark background.
- Generic caller.
- `Unknown` caller name.
- `Incoming FaceTime` text.
- Green accept button.
- Red decline button.
- Correct call icons.
- Minimal visual treatment.

The final design is intentionally restrained.

# Known Issues

The following features are intentionally not implemented yet.

### Face Tracking

The application does not currently detect the user's face.

### Facial Landmarks

The application does not yet identify:

- eyes
- mouth
- facial position
- head angle

### Replica

There is currently no separate replica.

The webcam simply displays the user's camera feed.

### Movement Following

There is no tracking or movement synchronization yet.

### Delay

There is no artificial movement delay.

### Horror

There are currently no:

- glitches
- flickers
- black eyes
- creepy smile
- distorted face
- independent movements
- horror sounds

This is intentional.

The first camera interaction should remain friendly.

---

# Design Goal

The purpose of v0.2.0 is not to scare the player.

It establishes the technical foundation for the most important transition in the experience:

> The character finally sees the player.

The next version will build on this moment and introduce the first genuinely interactive camera experience.
